# LettuceAI UI parity

Model loading and image-prompt preparation use a top-center progress toast instead of inline assistant-message status (user decision, 2026-10-15). The streaming cursor pauses during the hidden image directive and resumes after it closes. Model readiness, generation settlement and leaving the conversation dismiss the progress toast; ordinary notifications share the top-center host.

The inline author note is a compact single-line preview above the composer, with no heading or secondary row (user clarification, 2026-10-15). Long notes truncate without increasing its height. Editing opens a one-row Crisp Textarea that grows to four visible rows before scrolling; desktop Enter, Shift+Enter, Escape and blur-save behavior are retained. The compact phone preview retains the library's 44px touch target.

The composer's outer border stays neutral when its message input or inline author note receives focus (user decision, 2026-10-15).

Memory mode belongs in character settings only. Chat settings expose memory management and recovery notices without a mode selector or chat-level mode reset (user decision, 2026-10-15). Legacy's character editor exposes the mode at `old-code/src/ui/pages/characters/EditCharacter.tsx:2090-2143`; the rewrite's character settings screen is still pending.

Chat history searches titles and message previews, filters active/archived chats, sorts by activity date, and displays ten chats per page (user decision, 2026-10-15). "Last used" uses the existing `ConversationSummary.updated_at`; a separate last-opened timestamp is not available. Search and display pagination use the complete character-summary cache, whose backend cursors are still fetched eagerly. Desktop item actions remain context menus; compact layouts use a bottom Sheet.

Provider control failures use localized typed categories, including InUse and Malformed. Legacy provider/model editors displayed backend error strings (old-code/src/ui/pages/settings/hooks/useProvidersPageController.ts:298-320; old-code/src/ui/pages/settings/hooks/useModelEditorController.ts:1564-1577). Draft verification details retain the redacted provider message for a future editor flow.

Generated provider contracts expose stored-certificate validity with an InvalidPem reason, CertificateAlreadyImported details with the existing id, and optional redacted verification messages with MissingApiKey or InvalidApiKey reasons.

Locale moves from legacy webview localStorage to device UI state (`old-code/src/core/i18n/context.tsx:14,67-82`). A readable legacy key seeds the device choice; unavailable storage falls through to browser-language detection and then English (`old-code/src/core/i18n/context.tsx:62-77`). Persisting the detected device choice is best-effort. Only English resources are currently installed, so other retained locale choices use i18next's English fallback until their resources are added.

Filter refresh uses ContentFilterHit rather than the legacy development panel's five-second interval (`old-code/src/ui/pages/settings/SecurityPage.tsx:101-110`). Invalid legacy locale identifiers fall through to browser detection instead of being persisted as a choice, matching the legacy supported-locale check (`old-code/src/core/i18n/context.tsx:20-21,67-82`; registry at `old-code/src/core/i18n/locales/registry.ts:56-76`).

The shell uses Crisp's AppShell and TitleBar, following design-lab's rail and mobile tab layouts. Mobile and compact layouts show bottom navigation only on the exact Chats, Groups, Discover and Library root routes; Settings sits at the far right of those pages' title rows (user decision, 2026-10-15). Detail, settings, editor and unrelated routes hide bottom navigation. Desktop sidebar visibility on other pages is optional through Home's View menu and defaults to the existing visible behavior; the choice uses the existing device UI state. Hiding it gives Settings its index and back controls. The same AppShell stays mounted when navigation hides, preserving drafts across viewport changes. Groups and Discover content remains pending. Library follows design-lab/libraryApp/LibraryScreen.tsx: six filters, search, MediaCard and MediaTile grids, AudioItem rows and bottom action Sheets. All three lists are virtualized in the page scroller; 24-item pages load on demand and inactive media filters make no request. Search runs on the backend, including character descriptions and media source labels, instead of consuming every cursor. All filter totals remain visible through library_counts without reading inactive lists or treating loaded pages as totals. Virtual rows retain the demo’s 12px poster gap and 8px media gap. The sidebar uses cached Home identities and conversation avatar/title fallbacks without eagerly loading the whole character library. Its basic name/description editors retain unexposed fields; full legacy editors are pending (old-code/src/ui/pages/library/LibraryPage.tsx:211-222). Lorebook metadata has no description field; only its name is edited and its real entry count is loaded in the menu. File export uses the existing v3/UEC/world_info contracts instead of the demo’s synthetic JSON. Delete uses revision fences and confirmation without mock Undo. Media removal follows Rust’s in-use rejection instead of removing chat references. Library mobile navigation includes the demo’s central Create action; destination tabs remain the same four. Chats has character and recent-chat views; Settings exposes About, Providers and Models. Native window actions stay behind src/api. Window resize events update maximized/fullscreen state without polling. The restored frame has 16px corners; mobile and expanded windows remain square. Onboarding retains desktop window controls while hiding navigation.

Providers and Models retain the design-lab page layouts and connect their mock actions to typed API commands. Model export uses the backend's UEC format instead of the mockup's JSON label. Deletion requires confirmation because these APIs do not offer the mockup's undo. Deleting a provider with models requires a second confirmation naming those models before requesting cascade deletion. The mockup's runtime shortcut exposes the supported global context/KV defaults; threads and GPU layers are edited per local model. The available LoRA API manages image-generation adapters. These auxiliary sheets are functional integrations, not a claim of complete legacy editor parity.

Custom provider fields follow `old-code/src/ui/pages/settings/ProvidersPage.tsx:832-1130` and its TLS control at `:764-778`. Legacy flat camelCase fields now map to `ProviderConfig::Custom` in `crates/lettuce-models/src/lib.rs:115-196`; authentication uses the externally tagged `CustomAuth`, optional paths and role overrides retain null values, and disabling model discovery writes a null `models_path`. OpenAI and Anthropic retain their separate chat-path/auth defaults (`crates/lettuce-app/src/api/providers/mod.rs:394-414`). Blank saved keys are retained; no-auth accounts need no key. Required endpoint checks retain the legacy controller behavior (`old-code/src/ui/pages/settings/hooks/useProvidersPageController.ts:265-289`).

The chat model settings editor reuses the model editor fields with the same EditorRow layout, hints and aligned controls as the model editor, adapted to the drawer width. Reset all sits beside the model identity. Draft status, Discard and Save share one Sheet footer row outside the scroller; narrow layouts keep the status accessible and expand the two actions, matching the model editor. Changes still write only the conversation model settings layer.

Model editor groups controlled by a switch, including reasoning and prompt-cache retention, share an expanding/collapsing transition with the chat drawer. The transition uses Crisp collapse timing, disables exiting controls, and respects reduced motion.

KV cache uses one placement control, separate from model GPU layers and device selection (user decision, 2026-10-15). Single-GPU mode offers Automatic, System RAM and GPU; Pin/Split choices appear only with multiple GPUs enabled. Saved single-GPU Split values display as GPU without rewriting the configuration, and switching multiple GPUs back on restores their detailed choice. The separate attention offload switch is removed. Automatic preserves existing offload values and describes an explicit RAM/GPU preference. Explicit placement overrides that preference in both estimates and context creation. The GPU distribution preview covers a single GPU plus CPU as well as multiple GPUs. The context API now exposes its existing resolved single-GPU layer count as placement data, including zero GPU layers; the UI renders the remaining layers on CPU. Device labels use the returned device ordering for multiple GPUs and the selected device or memory-pool name for a single GPU. Sizing and distribution formulas are unchanged. With fewer than two eligible GPUs, the multiple-GPU toggle is hidden; a sole GPU is shown in the disabled Run on selector without writing a device override. The GPU section is hidden when the device list is empty or the backend lacks GPU offload. The layer bar follows design-lab ModelFlows.tsx GpuSplit (segmented strip plus a placement explanation), using actual estimates for CPU/GPU proportions and the correct selected device labels. Context and memory estimation uses a shaped skeleton only before its first result; refreshes retain the previous estimate.

GPU placement lives inside Context & memory (user decision, 2026-10-15). The local editor allows two original max-w-2xl columns (42rem each) with a 1.5rem gap. GPU cards move beside context/KV cards only when the content container reaches 85.5rem; smaller containers stack them at their existing width. Cards are never squeezed to obtain two columns. Each column has its own container context so controls retain the original responsive layout. There is no separate GPU navigation destination; machines without GPU support omit the GPU region.

GPU layers and Keep on the CPU are complementary sliders over the same resolved maximum. Both edit gpu_layers, the setting consumed by preview and generation; CPU edits write maximum minus the requested CPU count. The unused legacy cpu_layers setting is preserved without adding a parallel runtime path.

The same ModelEditorColumns layout puts Sampler and DRY in Generation's second column and On this device in Overview's second column. Existing card widths, rows and field semantics are retained; all three layouts share the 85.5rem content breakpoint and stack below it. Template loading fills its flex drawer body so the spinner and copy are centered in the available area.

Local model reasoning controls live in Generation directly after Adaptive P, using that section's existing chat/feature scope. Template & output no longer duplicates them.

Library grid artwork uses bounded backend thumbnails; image detail and save actions retain original media. Pagination, virtual rows, filter counts and card spacing are unchanged.

Library image batches contain 32 items. Usage discovery is deferred until opening the image menu; avatar actions use fresh typed references, and delete still performs its authoritative in-use check.

Character creation uses design-lab/screens/CreateCharacterScreen.tsx as its layout reference: Identity, Scenes, Details and Extras, with an inline card inside Identity, equal columns for Identity/Extras, a 3:2 Details layout, stacked compact layouts and actions outside the page scroller. The former side summary panel stays removed. Native file pickers replace the mock's browser upload areas; images still use assets_ingest, with no base64 over IPC. The inline import action uses the existing import flow and returns to Chats after committing the imported character, rather than claiming to prefill an unsaved wizard. A separate banner image, card description and prompt selections remain editable. The draft still starts from character_draft_default. Name and definition remain required; starting scenes remain optional and the model may use the app default. Backend revision and operation-id behavior, ordered lorebook attachment, unsaved-input confirmation and system Back behavior are retained. Voice selection, the companion Soul editor, crop editing, library image picks and AI creation remain outside this slice, rather than using the demo's fixed options.

Library character-create actions use the full `/characters/new` wizard, including the All and Characters empty states and the shared Create menu. Existing `/library?create=character` links redirect there with history replacement. Persona and lorebook creation keep their compact editors.

The Scenes step uses the scene list as its only source (user decision, 2026-10-16). An initial empty Scene 1 opens on desktop; compact layouts show the list first and open the selected editor as a full page. Header and system Back return to the list before leaving the step. Add a scene appends an empty scene, selects it and focuses its opening message. Edits update the selected card immediately; there is no separate editor draft or save action. Cards keep their Scene N title and show the opening underneath, with an explicit Empty state, a plain default badge and a selected background/border. Default is a toggle; scene deletion requires confirmation in the shared bottom menu, and deleting the last scene leaves the list empty. Scenes never block forward navigation. Empty scenes show a warning that they will be skipped on save; Skip replaces Continue only when there are no scenes. Final character save removes empty openings, reindexes survivors and repairs removed-scene references without changing the in-memory editor. Placeholder chips insert at the current selection. Direction is always visible in a three-row field that grows with its content.

Character creation exposes Off, Auto and Custom card gradients. Off disables both automatic and custom rendering; Auto follows the avatar; Custom retains its colors when changing modes. Start and end colors are required for Custom and the optional middle color can be added or removed with Crisp ColorPicker controls. Existing avatar-extraction results seed Custom when available; the legacy fallback palette is retained otherwise (old-code/src/ui/pages/characters/EditCharacter.tsx:336-345). Storage keeps the legacy [start, end, middle] order and preview places the middle stop between the endpoints (old-code/src/ui/pages/characters/EditCharacter.tsx:1163-1235). No new persistence or API command is introduced. Cards with a saved None gradient use the neutral theme surface instead of the component's name-derived tint.

Character mode defaults to Roleplay and offers Companion in Identity. The existing character_draft_default command accepts an optional mode and returns the domain CompanionSoulConfig defaults for Companion without writes. The UI waits for this typed response before changing the mode or allowing forward navigation; a failed read preserves entered data and the previous mode. Details has independent One-to-one chats, Group roleplay and Group conversation prompt slots; Companion appears only in Companion mode. Prompt lists are filtered by their exact kind, and inherited labels display the applicable app/bundled document name using the same fallback order as launch/policy.rs. Selections write direct_prompt_id, group_roleplay_prompt_id, group_conversation_prompt_id and companion_soul.prompting.prompt_template_id. Null means inheritance; names are never stored as identifiers. Switching modes retains prior selections. Companion creation retains the backend's existing required-model validation; Soul editing and model installation are separate flows.

Persona creation is a two-step wizard at /personas/new (Identity with the description, then Extras) built like character creation; there is no design-lab mockup. Library persona-create actions and old /library?create=persona links open it. Name and description stay required, as in legacy createPersonaReducer. Saving keeps legacy order: the persona, then its lorebooks in order, then the default persona, whose revision is read from personas_list. A failed lorebook attachment or default change keeps the saved persona and reports a warning. Nickname, design note and design reference images are kept; avatar crop editing, AI avatar generation and AI design-note writing are outside this slice. Import accepts only persona files through import_preview/import_commit. After creating or importing, the library opens on its Personas filter.

The character edit page has five tabs (Profile, Scenes, Chat, Look, Soul) over one form; Soul appears only for companion characters. Legacy had three (character, soul, settings) and showed Soul only for companions (`old-code/src/ui/pages/characters/EditCharacter.tsx:374-390,893-896`). Nothing is written until Save: legacy saved the whole form in one `handleSave` triggered from the top bar and offered Save and Discard in a sticky unsaved-changes toast (`old-code/src/ui/pages/characters/hooks/useEditCharacterForm.ts:489`, `old-code/src/ui/components/App/TopNav.tsx:575-590`, `EditCharacter.tsx:635`). The rewrite shows a save bar only while the form differs from what was loaded, saves against the loaded revision so a character changed elsewhere reports a conflict instead of being overwritten, then applies lorebook unbind, bind and reorder against the owner revision each step returns; a failed lorebook step keeps the saved character and warns. Legacy blocked Android back while changes were unsaved and showed a sticky Save/Discard toast (`old-code/src/App.tsx:1003-1024`, `old-code/src/ui/components/App/TopNav.tsx:529-537`); the rewrite confirms on every route change and adds a beforeunload guard. Legacy showed backend error text on a failed save (`useEditCharacterForm.ts:715`); the rewrite maps typed error codes. Voice choice is limited to audio-provider voices; a voice stored by other means stays until another is picked. Soul generation runs the Soul writer job from the edit draft and always goes through a review sheet before anything changes the draft; it sends up to three scenes with text as opening context and treats number shifts under 0.02 as unchanged (`old-code/src/ui/pages/characters/EditCharacter.tsx:176-190,555-570`, `old-code/src/ui/pages/characters/components/SoulGenerationReviewOverlay.tsx:112-120`). Scheduled notes save immediately and are not part of the save bar; the label is optional, the content is required, the repeat window defaults to 24 hours and empty means until the next repeat (`old-code/src/ui/pages/characters/components/CompanionScheduledNotesEditor.tsx:160-175,321-345,540-595`). Unlike legacy, which silently ignored an end before the start, the rewrite blocks saving it. Picked dates are local wall-clock values stored as epoch milliseconds, and instants before 1970 are kept exact. The schedule summary sentence and active-now preview are not ported. Still deferred: the chat appearance editor, avatar and banner crop, picking images from the media library, and listing voice profiles.

With feelings applied from a generated soul, every proposed value is applied, including shifts under 0.02 that the review list hides; legacy applied the whole merged config (`old-code/src/ui/pages/characters/components/SoulGenerationReviewOverlay.tsx:580`). A new scheduled note starts at the current time rounded to the minute (`old-code/src/ui/pages/characters/components/CompanionScheduledNotesEditor.tsx:51-53,154`).
